# AS V4.1 PDF 解析阻断修复

固定源码：`C:\codex项目\GiveMeFive-AS-V4.1`。主站为 4173，修改性浏览器验收使用同一源码的独立 4174 数据库。

## 已确认根因

1. Stress10 无答案卷六页实际有 3731 个提取字符。旧题号规则不认 `01 ...`，旧选项规则不认 `A ...`，因此上传和页段保存成功之后，候选题号、选项均为零。这不是数据库写入异常。
2. 中文艺术卷六页实际有 4840 个字符、60 个原有选项标记，但旧题号规则不认“第 N 题”，因此候选题号为零。
3. 双列选项和 `A B / C D` 图像选项必须按原生文字坐标识别。不能把正文中的单独 A/B 变量误切成选项。修复中以实际失败诊断定位到第 6、9 题，最终均切出 A–D。
4. 有答案版的原卷答案表采用“题号一行、答案下一行”。现按原生文字列坐标、相同列数和唯一题号进行匹配，不根据题意解题。10 条答案均来自提供的 PDF。
5. 40 页 Mechanics 每页原生文字均为零。原有 OCR 调用捕获组件错误后只保留概括警告；已补充逐页异常类型、消息、堆栈。实际首页面调用抛出 `FileNotFoundError / WinError 2`，找不到 Tesseract。
6. 文件任务为 `needs_review`，批次却汇总为 `failed`。原重试 SQL 只重新排队 `failed` 文件，导致部分“重试”没有作用。现同时支持两种文件状态。

## 修改文件

- `as-v3-reference/gmf_v3/pdf_core.py`：题号、双列及图像选项、共享材料边界、原生答案表、阶段诊断与 OCR 异常。
- `as-v3-reference/gmf_v3/contracts.py`：兼容旧数据的可选解析诊断字段。
- `as-v3-reference/gmf_v3/jobs.py`：重试状态修复、异常阶段与堆栈、按尝试次数保存诊断文件。
- `backend/bank.py`：导入阶段、实际写入与结构拒绝计数、零题原因、部分试卷的真实原卷题数。
- `backend/app.py`：仅所有者可查看原 PDF、删除失败任务；删除采用从列表归档，保留原件与作答。
- `backend/migrations/005_import_archives.sql`：新增归档表，不改写历史表数据。
- `dist/assessment/v4/ui.mjs`、`dist/assessment/index.html`：阶段与拒绝原因显示、失败任务删除确认及脚本更新标记。
- `tests/test_experience_audit.py`：普通题、中文题、双列图像、零题、数据库异常、重试、权限、保留原件与 OCR 降级回归。
- `scripts/audit-pdf-pipeline.py`：对任意输入 PDF 分别执行原生提取、底层切题、完整上传导入接口和考试交卷，使用独立数据库。

## 重现

在项目目录使用现有 `.venv\Scripts\python.exe -X utf8`：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m pytest tests/test_experience_audit.py tests/test_v41.py tests/test_pdf_segments.py -q
```

逐份 PDF 的诊断工具接收重复的 `--pdf` 参数，`--data` 必须指向新的隔离目录，`--out` 指向结果 JSON。不会修改原站的数据库。

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/audit-pdf-pipeline.py --pdf "待验证的 PDF 绝对路径" --data "runtime/新的隔离验收目录" --out "验收结果 JSON 绝对路径"
```

实际证据位于本聊天的 `outputs/parser-p0/`：`final-results.json`、`main-site-results.json`、`ocr-first-page-exception.json`、测试日志，以及主站重试前后、无答案交卷、原卷评分、共享图表和跨页题截图。
