# Topic 学习证据算法 v1

来源是现有 SQLite AnswerRecord、题目版本、评分版本和 Bookmark 标记；没有新建学习账本或训练掌握模型。Results 调用本次投影，Progress 调用长期投影。

1. 创建会话时冻结 Topic、题型、题目版本及答案引用。此前已在任意本人会话中出现的 Question ID 或同指纹内容，不能再记为未见独立题。打开过但未完成的题也保守地计为已见。
2. 第一轮、平台未提供答案且未标记辅助的作答才是独立候选；重试和“借助教材或提示”单列。每个稳定 Question ID 只增加一次独立样本。无法判断独立性的旧记录单列，不补猜。
3. 标准答案必须仍为 Verified，且与有效评分版本的答案引用一致。答案修订但尚未重评时，相关记录暂不参与对错诊断。管理员重评生成新评分版本，原作答不变。
4. 只有单一核心 Topic 参与对错统计。多核心 Topic 与关联 Topic 只增加关联证据数，不把一题错误归因于所有知识点。未分类记录单列。
5. 显示独立已评分题数、首次正确/错误、最近 30 天首次独立题表现、重做次数/独立题数、Question Type 分布及按日期的首次证据变化。未作答和未评分分别计数。
6. 猜对但不确定仍是原本正确的作答，不算错误；但不用于“较充分证据”的数量门槛。至少 5 道独立、无辅助、未标记不确定的题才显示“数据充分（仅描述表现）”。这是工程上的描述门槛，未经学生群体校准。
7. 在证据达到门槛、首次错误至少 2 道且首次错误比例大于 0.30 时，显示“可优先巩固”。这是可忽略的练习建议，不是能力等级或精确概率。
8. 从未测试的 Topic 显示“未评估”；有记录但不足时显示“数据不足”。不显示 0% 掌握，不输出 AP 1–5 分预测。

独立检查复用 PracticeSession，活动期间不开放逐题答案或重试。整组正确且答案仍可靠才安排 24 小时后的延迟复查；错误/未答回到修正，答案发生变化则不推进。到期复查使用新的未见公共题。通过不会自动移出错题集，也不表示永久掌握。提交后标记复查题为猜对，会追加状态修订；原成绩保留。

pyBKT 与官方 examples 已审查。它需要按学生、技能和顺序组织的可靠对错序列，并通过训练/评估验证参数。当前没有足够真实学生数据，未安装或训练 BKT，也没有把未经校准的输出包装为掌握概率。

自动化证据：`tests/test_reviews.py`、`tests/assessment-evidence.test.mjs`。覆盖重复作答去重、辅助、未评分、综合题关联、证据门槛、不确定题、答案修订、原事实保留、独立整组规则、24 小时到期和失败回修正。
