# GiveMeFive V4.3 — 单一主线：管理员多课程发布 → 学生双来源练习

状态：2026-10-27 确立的产品与实施主线；**本文件是架构及验收基线，不表示功能已实现**。

## 唯一产品目标

管理员无需编辑 GitHub 源码，即可在后台创建/编辑/发布新课程、Unit/Topic 和配套教材，导入并审核公共题库、题组和试卷；学生登录后选择任意已发布课程，可以使用管理员发布的公共题目进行练习/模考，也可以上传自己的 PDF/DOCX 试卷、逐题校对并私人作答。两条来源始终明确区分。已有 Pathline、Mind Flow、Assessment 与 Progress 保持统一的 Course/Unit/Topic ID 及 Learning Ledger。

可选付费的**托管/数据库/存储服务**，不因部署费用提前锁定学生收费产品策略。不预设 30–50 人是永久容量上限。

## 不可变产品边界

1. **多课程是数据能力**：课程、Unit、Topic、课程内容、关联题库通过后端数据库及私有对象存储管理。不能每增加一门课就修改/重新构建前端或复制一个网站。
2. **管理员公共库**：课程/题目经草稿 → 人工校对 → 发布后才可供学生练习。可撤回；已进行的考试锁定题目和答案版本，不受后来修改影响。管理员上传素材必须记录版权来源/授权与作者，未获再分发授权不得对学生公开。
3. **学生私人库**：学生 PDF/DOCX 上传 → 结构抽取 → 原图对照逐题校对 → 确认 → 私人练习/考试。默认仅本人可见，不因给同一课程打标签就进入公共题库；转为公共必须经过独立管理员审核及授权。
4. **评判**：只能根据管理员核对或原卷可靠答案判分；无答案或证据不足显示“未评分”，不猜答案，不借助 AI 生成、评分或核验（Assessment 冻结边界）。
5. **统一学习记录**：保持旧课程 `ap-physics-c-mechanics-2026-27` 的标识及历史数据。每门课程的 Topic ID 和发布版本均有稳定标识；成绩/错题/学习 Evidence 可溯源具体用户、Course、Topic、QuestionVersion。
6. **权限和持久化**：管理员写入与学生读写分离；所有私人原卷、题图、作答、记录经服务端校验 owner_id，数据库与文件存储都强制隔离；重启/更新后数据保留。
7. **现有功能不倒退**：41 Topics Pathline 教材、MF 正倒计时/Review & Repair、Assessment 现有完整题目流程、Progress 不能删减。课程资源和个人记录永远分离。
8. **源码安全**：现有 GitHub Public 不准包含私人学生数据、服务凭据和受限教材资源。GitHub CI 的私有资源配置独立修复，不以跳过完整性审计替代完成。

## 目标数据与服务（可渐进迁移，不需推翻原 V3/V4 题库）

- `courses`：course_id、title、subject、status(draft/published/archived)、owner/admin、metadata、发布版本；
- `course_units` / `course_topics`：课程作用域稳定 ID、顺序、标题、描述；约束跨课程引用；
- `course_content_sources` / `course_content_versions`：原始 PDF/图片/可编辑内容、来源许可、资产哈希、Topic 映射、发布快照。教材包及题图由对象存储或受控文件存储按需分发；
- 复用已有 `questions`、`question_versions`、`answer_keys`、`v4_meta`、`v4_sets`：增加按 course_id / topic_id 可检索索引、来源、发布版本和 provenance；避免复制出不兼容的第二套题库；
- `users` / `memberships` / `roles`、`student_private_imports`、`attempts`：用户身份、可用课程、文件归属、历史考试快照；
- 服务：`CourseCatalog`（创建/编辑/发布）、`ContentImport`（教材源文档解析/编辑）、`QuestionBank`（管理员审核发布）、`Practice`（公共/私人练习）、`Identity`（学生账号）。
- 后端 API 应有课程列表/详情/发布版、管理员课程 CRUD 与发布、课程内容与题库导入审核、学生个人导入与确认、练习组卷和成绩。HTTP 响应不信任客户端提供的角色或 owner_id。
- 新课程公开发布后能立刻在 PL/AS 的课程选择中出现；旧课程原标识及已有学习记录继续有效。

## 唯一实施主线（每阶段必须跑通真实纵向流程）

### M1｜多课程核心（优先开始）
- 在保留原有存储结构下新增正式 Course/Unit/Topic 数据层与受控迁移，将现有 7 Units/41 Topics 作为已发布首门课程注册，原内容哈希保持不变。
- 后端课程列表/读取和管理员新增/编辑/发布接口；前端从 API 动态读取课程/Unit/Topic，移除 `Bank.catalog` 仅允许唯一 course_id 的硬编码校验。
- 用纯测试数据创建第二门“测试课程”，带 1 Unit / 2 Topics；无需新的前端构建即可显示；未发布课程对学生不可见。

### M2｜管理员内容与公共题库
- 管理员网页可以新增课程、修改单元/知识点顺序、上传并关联教材 PDF 或可编辑课程内容，预览/人工校对，再发布并保持版本记录。
- 复用管理员 PDF/DOCX 试卷解析与题库：逐题校对原图、题干、选项、答案来源、关联 Topics；草稿→发布/撤回；创建公开练习集和 MCQ 试卷。课程创建和题目导入是独立操作；无题课程亦可以上线 PL。
- 未核对答案允许题目发布为“待确认/不计分”（是否允许公开由发布审核控制）；保留原始文件和改动版本。
- 不以 AI 取代人为校对；复杂教材不可自动识别时保留原文并标为需人工映射。

### M3｜学生双题源与数据可靠性
- 学生按已发布课程选择公共题库，按 Unit/Topic 或题组练习/模考；个人“我的试卷”独立上传 PDF/DOCX、逐题校对、私人考试。明确显示题目来源，默认不混库。
- 两种来源共用保存、计时、结果、错题/题目版本机制；无可信答案明确不评分；测试两个独立学生互不可见私人数据。
- 正式身份系统、受控注册/邀请、跨设备学习记录与 Progress 持久化；不沿用共享测试管理员 Cookie。

### M4｜完整线上交付与扩展
- 选支持 FastAPI + DOCX/LibreOffice + 后台任务 + HTTPS 的**持久计算服务**，搭配持久数据库、私人原始文件/课程对象存储及定期备份；允许评估付费托管，需明示月成本和数据/地区限制。当前 ChatGPT Sites 可保留为个人 PL/MF 预览，不当作完整多用户后端。
- 按最小权限隔离管理员和学生；限制文件大小和解析队列，处理恶意文件、并发、超时及恢复；实际演练备份还原。
- 真正用两个学生账号跨设备验收；确认稳定再讨论正式公开、支付与定价。

## 最小端到端验收（整条主线的准绳）

管理员创建并发布**第二门测试课程**，新增 Unit/Topic 与一份有来源的阅读资料；导入两道 MCQ（1 道由管理员核对答案、1 道无可靠答案），人工校对后发布。学生 A 登录后在课程列表看到该课程，阅读新教材并答管理员的题；第一题能按可靠答案评分，第二题显示未评分。随后 A 上传自己的 PDF/DOCX，逐题核对并完成私人考试；学生 B 能使用公共题库，但不能查看 A 的原卷、题图、答案、会话、学习记录或文件。退出重登/重启后数据保持；既有 AP Physics C Mechanics、原 Pathline、MF 与 Assessment 功能无回归。

**未达到这一验证，不能称“GMF 多课程双题库平台已上线”。**

## 交付规则

每一阶段提交 GitHub 单独分支、迁移、自动化测试、必要时的真实浏览器验收和失败清单；不得强推、不得覆盖 main。工作顺序始终是 M1 → M2 → M3 → M4，不用单纯修饰 UI 或让 CI 绿灯取代核心产品能力。课程/公共题库/个人试卷需独立授权与数据隔离验证。现实部署允许使用付费云服务，但消费前需明确费用并取得用户授权。
